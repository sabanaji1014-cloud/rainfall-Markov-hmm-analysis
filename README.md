# Rainfall & Drought Analysis with Markov Chains and a Hidden Markov Model

Course project for **Stochastic Processes 1** (Instructor: Dr. Safari).

**Authors:** Mehrnaz Yazdani (610301201), Saba Naji (610301190)

## Overview

This project models the day-to-day and month-to-month behavior of rainfall/drought
conditions as a discrete-time Markov chain, and extends the analysis with a Hidden
Markov Model (HMM). It uses about 12 years (2009–2020) of daily weather observations.

The analysis has three parts, all reproduced by the single script
[`src/analysis.py`](src/analysis.py):

1. **Part 1 — Binary drought/wet classification.** The Standardized Precipitation
   Index (SPI) is computed from monthly and yearly rainfall averages and converted to
   a binary state (`0` = drought, `1` = wet). Transition matrices are built for lags
   1 through 5 (both months and years), and AIC/BIC are used to compare the
   candidate Markov models. The best-fitting model uses the previous **year** as the
   single lag (AIC = 19.11), matching the result in the report.
2. **Part 2 — Multi-category rainfall classification.** Mean rainfall is split into
   10 categories, and one-day and two-day transition matrices (with AIC/BIC) are
   computed between categories.
3. **Part 3 — Hidden Markov Model.** A 2-state Gaussian HMM is fit to standardized,
   monthly-averaged weather features (min temperature, wind, humidity, cloud cover,
   pressure, and an encoded weather description) and the inferred hidden states are
   compared against a simple rainy/sunny classification of the same months
   (threshold: the median monthly rainfall). The two agree on about 62% of months.

The full write-up, methodology and results tables are in [`report/`](report).

## About `analysis.py`

This single script replaces what were originally five separate, overlapping draft
scripts (`project.py`, `project2.py`, `ST_part_b.py`, `video_way.py`, `video_way2.py`)
plus a broken, Colab-only `HMM.py`. Consolidating them removed a lot of duplicated
code, and in doing so surfaced a few real issues that are now fixed:

- **A corrupted row in the source data.** `project.xlsx` has one row where the date
  is a stray `0` and the other columns hold unrelated numbers. Read naively, that
  row gets parsed as the date 1970-01-01, which silently corrupts every later
  resample/rolling calculation (the original per-row loops happened to skip it by
  accident, since a falsy `0` failed their `if date_cell:` check). `analysis.py`
  filters it out explicitly and documents why.
- **AIC/BIC results weren't being collected anywhere.** The original scripts printed
  the AIC/BIC for each of the 5 lags to the console one at a time, overwriting the
  same variables on every loop iteration -- so reproducing the report's summary
  table meant copying numbers out of the console by hand. `analysis.py` collects
  every lag's result into one table, `aic_bic_binary_markov_summary.csv`. (After
  fixing the data issue above, these numbers now match the report's Part 1 table
  exactly, e.g. AIC = 19.11 for the previous-year model.)
- **Part 3 (HMM) is now complete and runs.** The original `HMM.py` depended on an
  external, already-preprocessed dataset (`data_new.xlsx`) that was never part of
  this repository, and still referenced a couple of undefined variables left over
  from the notebook it was copied from. `analysis.py` implements Part 3 following
  the steps described in the report -- monthly-averaged features, standardization,
  a 2-state Gaussian HMM, and a rainy/sunny comparison -- entirely from
  `data/raw/project.xlsx`, and it runs end to end.

Two exploratory pieces from the original files that were **not** used to produce the
final results are kept as clearly-labeled, self-contained functions rather than
dropped:

- `classify_spi_severity` -- the 9-level SPI severity scale (from `project.py`).
- `compute_spi_manual_integration` -- an alternative SPI calculation via direct
  numerical integration instead of `scipy.stats.gamma` (from `project2.py`). One
  small arithmetic bug (missing parentheses in the inverse-normal approximation)
  is fixed, with a comment explaining the correction.

Beyond this, the underlying methodology is unchanged: same SPI formula, same
binary/category definitions, same transition-matrix construction.

## How to run

```bash
pip install -r requirements.txt
cd src
python analysis.py
```

This regenerates every file in `data/processed/` from `data/raw/project.xlsx`.

## Data

`data/raw/project.xlsx` contains daily observations from 2009 to 2020 with the
columns: `Year` (date), `Weather` (text description), `Max`/`Min` (temperature),
`Wind`, `Rain`, `Humidity`, `Cloud`, `Pressure`.
